# 0007. Build SEO with svelte:head and typed helpers

- **Status:** Accepted
- **Date:** 2026-10-19

## Context

Every page needs a unique title and description, a canonical URL, Open Graph tags and, where
Google supports it, structured data (JSON-LD). The SvelteKit SEO guide recommends returning
SEO data from `load` functions and rendering it in `<svelte:head>`.

On 2026-10-19 the candidate libraries were: `svelte-meta-tags` 5.0.3 (maintained, Svelte 5
support), `svelte-seo` 2.0.0 (last published 2025-11) and `sk-seo` 0.5.4 (last published
2025-05, no Svelte peer range).

## Decision

- No SEO library. One `Seo.svelte` component renders all tags from typed props.
- Pages return an `seo` object from their `load` function; the root layout renders it.
- Structured data is typed with `schema-dts` (types only, nothing shipped to the browser) and
  serialized safely, escaping `<` so content cannot close the script tag.
- Structured data limited to types Google supports today: `Organization` and `WebSite` on the
  homepage, `BlogPosting` and `BreadcrumbList` on articles. FAQ rich results are not used
  (Google stopped showing them in 2026), so FAQ content is plain HTML.
- `sitemap.xml` and `robots.txt` are generated by endpoints from the same route data.

## Consequences

- Zero runtime dependencies for SEO, and full control over every tag.
- We maintain about 100 lines of SEO code ourselves.
- If requirements outgrow it, `svelte-meta-tags` is the drop-in candidate.
